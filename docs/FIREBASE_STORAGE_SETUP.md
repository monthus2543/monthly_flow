# ตั้งค่าอัปโหลดรูปโปรไฟล์

โค้ดเลือกไฟล์จากเครื่องก่อน จากนั้นอัปโหลดเมื่อกดบันทึก แล้วนำ download URL ไปเก็บใน Firebase Authentication `photoURL` ชื่อโปรไฟล์ยังอยู่ใน `displayName` บัญชีออฟไลน์ต้องเชื่อมต่อ Google ก่อนใช้การอัปโหลดรูป

## การตั้งค่าฝั่ง Firebase

1. เปิด Firebase Console → โปรเจกต์ `monthly-flow-75287` → Storage → Get started
2. หาก Firebase ขอให้เปลี่ยนแผน ต้องใช้ Blaze พร้อมบัญชีเรียกเก็บเงิน เจ้าของโปรเจกต์เป็นผู้ดำเนินการขั้นตอนนี้ ตั้ง budget alert ตามที่ต้องการ (alert ไม่ใช่เพดานค่าใช้จ่าย)
3. สร้าง default bucket แล้วตรวจว่าชื่อตรงกับ `monthly-flow-75287.firebasestorage.app` ซึ่งเป็นค่าที่มีใน Android google-services.json หากแตกต่างต้องดาวน์โหลดไฟล์ตั้งค่าใหม่ให้ตรงกับ bucket จริง
4. ใน Storage → Rules นำเนื้อหาจากไฟล์ `storage.rules` ของโปรเจกต์ไปใส่แล้ว Publish กฎนี้อนุญาตผู้ใช้ที่เข้าสู่ระบบให้อ่าน สร้าง และลบรูปในโฟลเดอร์ของตัวเองเท่านั้น ไม่เปิดทุกไฟล์สู่สาธารณะ
5. หากใช้ Firebase CLI ที่เข้าสู่ระบบแล้ว ใช้ `firebase deploy --only storage --project monthly-flow-75287` แทนขั้นตอน 4 ได้ เครื่องปัจจุบันไม่พบ Firebase CLI จึงไม่ได้เผยแพร่กฎจากการพัฒนารอบนี้
6. เพิ่ม native dependency แล้วต้อง Stop → Run แอปใหม่ การ Hot Reload อย่างเดียวไม่โหลด firebase_storage

ข้อกำหนด Blaze: https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024
เอกสารการอัปโหลด: https://firebase.google.com/docs/storage/flutter/upload-files

## รูปและกฎการเก็บ

- Path: `users/{Firebase UID}/profile/{random ID}.jpg|png|webp`
- รองรับ JPG, PNG และ WebP ไม่เกิน 5 MB ตัวเลือกรูปขอย่อด้านยาวไม่เกิน 1024 px และลดคุณภาพเป็น 85 ตามความสามารถของ image_picker
- แต่ละการอัปโหลดใช้ไฟล์ใหม่ ไม่เขียนทับรูปเดิมก่อนบันทึกโปรไฟล์สำเร็จ
- ถ้าบันทึกโปรไฟล์ล้มเหลว จะพยายามลบไฟล์ใหม่และคงรูปเดิม หากไม่มีอินเทอร์เน็ตตอนลบอาจมีไฟล์ค้าง
- รูปเก่าที่เคยบันทึกสำเร็จยังเก็บไว้ ไม่มีระบบลบรูปย้อนหลังอัตโนมัติ ควรวางแผนการเก็บ/ล้างไฟล์หากใช้งานจำนวนมาก
- Download URL ของ Firebase มี token ผู้ที่ได้รับ URL สามารถโหลดรูปได้ จึงไม่ควรใช้รูปโปรไฟล์เก็บข้อมูลลับ แม้กฎ SDK จะจำกัดสิทธิ์ที่เจ้าของไฟล์
- ไม่เปลี่ยนรูปของบัญชี Google ต้นทาง

## การทดสอบจริงหลังตั้งค่า

เข้าสู่ระบบ → ตั้งค่า → แตะรูปโปรไฟล์ → เลือกรูปจากเครื่อง → บันทึก ตรวจเปอร์เซ็นต์อัปโหลดและรูปในหน้าตั้งค่า จากนั้นเปิดแอปใหม่ รูปควรยังอยู่ ตรวจไฟล์ใน Storage ตาม UID และตรวจ photoURL ใน Authentication

ทดสอบกรณียกเลิกการเลือกรูป ไฟล์ใหญ่หรือไม่รองรับ อินเทอร์เน็ตขาด และผู้ใช้อื่นอ่าน/เขียน path ของบัญชีอื่นไม่ได้ด้วย การทดสอบจำลองไม่ยืนยันว่า bucket และกฎใน Firebase จริงถูกตั้งค่าแล้ว
